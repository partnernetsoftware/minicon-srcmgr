# MiniCon SrcMgr 0.2.1 beta

**This is a pre-release.** The clean-image and five-participant courts still have
not been run, and this page says so rather than implying they passed. 0.2.1 closes
the sentence 0.2.0 left open: the result is written where the three sides are read.

## What is new since 0.2.0

- **A result pane in the window.** Enter in the conflict center opens base,
  current and incoming read-only, labelled by stage role, beside a fourth pane
  you can edit. `i` opens it from the incoming side and `0` opens it empty; the
  caret shows as a bar in the text plus an `L{line}:{col}` readout.
- **Editing that behaves like an editor.** Enter breaks a line, Ctrl+Z undoes and
  Ctrl+Y redoes (32 steps), selection and paste work, and a composition arrives
  as one committed text event. An insertion that would cross 2 MiB or 200 000
  lines is refused whole instead of being cut.
- **Search across the four panes.** Ctrl+F opens a find field that counts matches
  live in the result and the three sides. It is a plain byte search: no case
  folding and no regex, and the panel says what it counted.
- **A save that keeps the file's own shape.** Ctrl+S writes through a temporary
  file and a rename, under a `save-result` job record. UTF-8, UTF-8 with a BOM
  and UTF-16LE with a BOM are written back as they were, an unknown encoding is
  refused by name rather than re-encoded, and the file's newline style is
  preserved (CRLF stays CRLF; a mixed file is left as the editor wrote it).
- **The index still decides.** Marker-like lines are a warning on save and again
  on stage, never a refusal. Space stages the saved copy through the existing
  0.2.0 check, which re-reads the index and refuses to call a path resolved while
  Git still lists it as unmerged.
- **A found defect, fixed.** The marker check compared raw bytes, so a marker on
  the first line of a file with a BOM was never reported. The BOM is now dropped
  before scanning, and the fixture asserts the warning on save and on stage.

## What this release does not prove

- **The clean-image court did not run (C6).** Nobody has launched this archive on
  an image that never had the product or the Rust toolchain. The runbook and the
  receipt it produces are in `docs/qualification/clean-image.md`.
- **The five-participant court did not run (C7).** Four of five unaided
  completions of clone → stage/commit → pull → push has not been observed, and no
  participant has been asked to finish a conflicted merge in the result pane. The
  protocol is in `docs/qualification/five-users.md`.
- **No GUI journey qualification on any cell for this version.** Only Windows
  x86_64 has ever had a GUI journey qualified (0.1.0); the other cells are
  qualified to "starts and performs real Git reads on a fixture". macOS is not
  signed or notarized: clear the quarantine flag once after extracting with
  `xattr -d com.apple.quarantine minicon-srcmgr`.
- **No composition display.** The window has no composition stream, so a
  composition is inserted when it commits; no preedit line is drawn.
- **No search navigation.** The find field reports a count; it does not jump
  between matches, fold case or accept a regular expression.
- **No syntax colouring, word wrap or multiple cursors.** Binary, symlink,
  submodule and delete/modify conflicts stay refused by name, as in 0.2.0.

## Requirements

Git must already be installed and on `PATH` (or pass `--git <path>`), version
2.43 or newer. The product does not bundle Git. Windows x86_64 needs Windows 10
or later; Windows ARM64 needs Windows 11 on ARM; macOS needs 14 or later; Linux
needs glibc 2.39 (Ubuntu 24.04).

## Verify

```text
sha256sum -c SHA256SUMS.txt                                   (macOS, Linux)
```
