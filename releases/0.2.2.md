# MiniCon SrcMgr 0.2.2 beta

**This is a pre-release, and it changes the command line.** The clean-image and
five-participant courts still have not been run. The command line now uses the
standard `git` spelling and the earlier private spelling is **removed**: a script
written for the old `minicon-srcmgr` will stop working until it is updated. The
table below is the whole migration.

## What is new since 0.2.1

- **The `git` invocation.** The subcommand comes first. `-C <path>` selects the
  repository and is accepted before the subcommand only, exactly as `git` accepts
  it; without `-C` the repository is discovered from the current directory by
  walking up to the first ancestor that holds a plain `.git` directory. `-C ""`
  changes nothing, and `-C<path>` is accepted in the attached form.
- **Machine-readable status is Git's own.** `status --porcelain=v2 -z` and
  `status --porcelain -z` return the bytes `git` returns for the same repository,
  including a rename's score and second operand, because the product passes the
  command through instead of rebuilding the records from its own snapshot.
- **The Git names.** `log`, `check-ignore`, `config` and `branch -m` replace the
  private names. `branch -m [<old>] <new>` renames through Git so the upstream
  follows, under a job record, with the old and new values read back; a
  destination that already exists is refused by Git before anything moves.
- **`--` ends options.** `stage -- -dash.txt` stages a path that begins with a
  dash; without `--` the same word is an option and the refusal says so.
- **Usage errors exit 129**, as `git` does; a refused or failed operation exits 1.
  An unknown option is refused by name, never ignored.

## Migration from 0.2.1

| 0.2.1 | 0.2.2 | Notes |
|---|---|---|
| `status <worktree>` | `status [-C <path>]` | Without `-C`, the current directory |
| `stage <worktree> <path>...` | `stage [-C <path>] [--] <path>...` | Paths are still literal |
| `unstage <worktree> <path>...` | `unstage [-C <path>] [--] <path>...` | |
| `commit <worktree> -m <msg>` | `commit [-C <path>] -m <msg>` | A saved draft is still used without `-m` |
| `branch <worktree> list` | `branch [-C <path>] [--list \| list]` | All three list |
| `branch <worktree> create <n>` | `branch [-C <path>] create <n>` | A SrcMgr verb; `git switch` is its own |
| `branch <worktree> switch <n>` | `branch [-C <path>] switch <n>` | |
| `history <worktree> --skip N --limit N` | `log [-C <path>] --skip N --limit N` | |
| `ignore <worktree> <path>` | `check-ignore [-C <path>] [--] <path>` | Exits 1 when nothing matches, like `git` |
| `setting get\|set <key> [value]` | `config get\|set <key> [value]` | SrcMgr preferences, not Git configuration |
| `draft <worktree> save\|show\|clear` | `draft [-C <path>] save\|show\|clear` | |
| `diff <worktree> <path> [--staged]` | `diff [-C <path>] [--staged] [--] <path>` | |
| `hunk <worktree> list <path>` | `hunk [-C <path>] list [--staged] [--] <path>` | |
| `hunk <worktree> stage\|unstage <path> <n>` | `hunk [-C <path>] stage\|unstage [--] <path> <n>` | |
| `remote <worktree> list\|tracking` | `remote [-C <path>] list\|tracking [--json]` | |
| `remote <worktree> add\|set-url\|rename\|remove ...` | `remote [-C <path>] add\|set-url\|rename\|remove ...` | `--yes` still applies; otherwise preview |
| `fetch <worktree> <remote>` | `fetch [-C <path>] [--json] <remote>` | |
| `pull <worktree>` | `pull [-C <path>]` | Still fast-forward only |
| `push <worktree> <remote>` | `push [-C <path>] <remote>` | |
| `trust grant\|revoke <worktree>` | `trust [-C <path>] grant\|revoke` | |
| `gui [worktree]` | `gui [-C <path>]` | |
| `clone <url> <dir>` | `clone <url> <dir>` | Unchanged |

The old names `history`, `setting` and `ignore` print the replacement and exit
129. An old shape that put the repository after the verb (`status <worktree>`)
is refused with the line `takes no path; the repository comes from -C <path> or
the current directory`, also with exit 129.

**Not changed.** Trust is still checked before any repository Git runs, whichever
way the repository was found; a write that is refused leaves the repository
byte-identical; paths are literal, never patterns. The window does not use this
command line and is unaffected.

## What this release does not prove

- **The clean-image court did not run (C6).** Nobody has launched this archive on
  an image that never had the product or the Rust toolchain. The runbook is
  `docs/qualification/clean-image.md`.
- **The five-participant court did not run (C7).** No participant has been asked
  to complete the daily journey. The protocol is `docs/qualification/five-users.md`.
- **Not every `git` option is accepted.** `log` takes `--skip` and `--limit` only;
  `status` has no long format; there is no `add -p`, no aliases and no
  configuration file. Compatibility is the invocation and the porcelain bytes,
  not the whole of `git`'s option surface.
- **Current-directory discovery is narrower than `git`'s.** A `.git` file (a
  linked worktree) and a bare repository are refused, as they were before; the
  refusal says to pass `-C`.
- **No GUI journey qualification on any cell for this version.** Only Windows
  x86_64 has ever had a GUI journey qualified (0.1.0). macOS is not signed or
  notarized: clear the quarantine flag once after extracting with
  `xattr -d com.apple.quarantine minicon-srcmgr`.
- **The `control` verbs are 0.2.3** and history moves (cherry-pick, revert, reset,
  tags, amend) are 0.2.4.

## Requirements

Git must already be installed and on `PATH` (or pass `--git <path>`), version
2.43 or newer. The product does not bundle Git. Windows x86_64 needs Windows 10
or later; Windows ARM64 needs Windows 11 on ARM; macOS needs 14 or later; Linux
needs glibc 2.39 (Ubuntu 24.04).
