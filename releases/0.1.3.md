# MiniCon SrcMgr 0.1.3 beta

**This is a pre-release.** Two release gates have not been run, and this page says
which and why. Everything else 0.1.2 delivered is here, plus the surfaces 0.1.0's
notes named as missing.

## What is new since 0.1.2

- **Clone inside the window.** URL, absolute destination, branch and depth, with a
  review that names the exact effect. Approving sends one one-use ticket; nothing
  is transferred before that. Clone still keeps `--no-checkout`, and a repository
  whose worktree is empty now says so: `o` reviews writing HEAD's tree, and only
  `y` writes it.
- **A failed clone is inspectable.** The target is kept, `i` lists what is in it,
  `x` reviews a removal that only `y` performs, and a directory that existed before
  the attempt is never offered for deletion.
- **Remotes panel.** One row per remote with its redacted fetch URL, a push URL
  when it differs, and the configured refspec. Add, Set URL (fetch or push),
  Rename, Remove and Fetch this remote, each reviewing its local effect first; a
  refusal leaves the configuration byte-identical.
- **Simplified Chinese.** Every control, status line, footer hint, pane title and
  refusal the product composes is available in English and 简体中文, with a visible
  choice that persists. Paths, object ids, refspecs and branch names stay literal,
  and Git's own error text is shown as Git printed it.
- **Divergence is named, not counted.** When both sides advanced, the status line
  shows each tip by short OID and subject and when the fetch that produced them
  ran. Pull refuses from that state rather than choosing an integration.
- **An unfinished integration blocks writes.** Merge, rebase, cherry-pick, revert
  and am are read from Git's own metadata; stage, commit, pull and push refuse
  with the operation named, and `t` opens a configured terminal at the repository.

## What this release does not prove

Stated here so nobody is misled:

- **The clean-image court did not run (C6).** Nobody has launched this archive on
  an image that never had the product or the Rust toolchain. The runbook and the
  receipt it produces are in `docs/qualification/clean-image.md`.
- **The five-participant court did not run (C7).** Four of five unaided completions
  of clone → stage/commit → pull → push has not been observed. The protocol is in
  `docs/qualification/five-users.md`.
- **No GUI journey qualification on any cell for this version.** The Windows
  x86_64 GUI journey qualified in 0.1.0; the other cells are qualified only up to
  "the executable starts and performs real Git reads on a fixture".
- **macOS is not signed or notarized.** On macOS 15 or later, clear the quarantine
  flag once after extracting: `xattr -d com.apple.quarantine minicon-srcmgr`.
- **No accessibility qualification, no CJK/clipboard composition test, no
  long-session resource measurement.**

## Requirements

| Cell | Minimum |
|---|---|
| Windows x86_64 | Windows 10 or later, x86_64 |
| Windows ARM64 | Windows 11 on ARM64 |
| macOS x86_64 | macOS 14 on Intel, untested; built on macOS 15 |
| macOS ARM64 | macOS 14 on Apple Silicon, untested; built on macOS 15 |
| Linux x86_64 | Ubuntu 24.04 x86_64, glibc 2.39 |
| Linux ARM64 | Ubuntu 24.04 ARM64, glibc 2.39 |

Git must already be installed and on `PATH` (or pass `--git <path>`), version 2.43
or newer. The product does not bundle Git.
